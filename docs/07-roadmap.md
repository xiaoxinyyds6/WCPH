# 07 · 落地规划

> 对应文档规范 **g**：上线计划、用户增长设计、运营机制、商业闭环与后续版本迭代方向。
> 当前状态：功能可演示，**尚未上线**。以下时间以「立项启动日 T0」为相对刻度，可按实际排期平移。

## 1. 上线计划

### 1.1 三个阶段

| 阶段 | 时间 | 目标 | 关键事项 | 验收标准 |
|---|---|---|---|---|
| T0 合规整改 | 第 1–2 周 | 达到可提交审核状态 | 替换默认管理员口令；移除 `square` 的 `ADMIN_OPENIDS`；真实短信或关闭验证码入口；补图片/AI 输出内容安全；配置订阅消息模板；建组合索引与集合权限；隐私协议/免责声明/类目资质 | 上线检查清单全绿；真机主链路通过 |
| T1 小范围灰度 | 第 3–4 周 | 验证真实留存与内容治理 | 邀请 50–100 名种子用户；开启审核与举报 SLA；观察 AI 失败率、问诊完成率、提醒完成率；收集反馈 | 7 日留存 ≥ 25%；AI 问诊成功率 ≥ 90%；无重大内容安全事故 |
| T2 正式发布 | 第 5–6 周 | 公开可用 | 提交微信审核；配置小程序搜索关键词；发布首批官方内容；建立客服/举报入口 | 审核通过；日活与留存达到基线；故障可 30 分钟内响应 |

### 1.2 上线前必须清零的风险

| 风险 | 当前状态 | 上线前动作 |
|---|---|---|
| 默认管理员口令 | `admin / Admin@123456` 仅演示 | 按 [deploy.md §5.2](./deploy.md#52-修改默认口令上线必做) 替换并失效默认常量 |
| 管理员白名单 | `square` 仍保留 `ADMIN_OPENIDS` | 删除硬编码，统一查 `admins` |
| 短信验证码 | 云函数直接回传验证码 | 接真实短信服务商并移除回传字段；或暂时隐藏验证码入口 |
| 图片内容安全 | 未校验 | 接 `mediaCheckAsync`，失败转人工 |
| AI 输出安全 | 未二次审核 | 输出过 `msgSecCheck`，命中即降级为规则建议 |
| 订阅消息 | 模板 ID 为空 | 公众平台申请模板，两处同步填写，上传定时触发器 |
| 数据库索引/权限 | 部分索引未建 | 按 [data-model.md §7](./data-model.md#7-索引建议) 创建；集合设为「所有用户不可读写」 |
| 类目与资质 | 未确认 | 按「工具 > 健康管理」提交；避免诊断/处方表述；如被要求医疗资质，准备合作兽医/机构证明 |
| 隐私合规 | 仅定位权限声明 | 补隐私政策、用户信息用途、数据删除入口 |

## 2. 用户增长设计

### 2.1 冷启动（0–1,000 用户）

| 渠道 | 动作 | 成本 | 预期 |
|---|---|---|---|
| 校园/宠物社群 | 与高校宠物社团、同城遛狗群合作，发急救指南与问诊体验码 | 低 | 首批 200–300 名高互动用户 |
| 宠物医院/门店 | 在前台放小程序码，主打「就诊前先整理症状」 | 中 | 精准需求用户，转介绍率高 |
| 内容平台 | 小红书/抖音发「猫咪呕吐要不要去医院」等场景短视频，挂小程序 | 中 | 带来搜索与分享流量 |
| 微信搜一搜 | 配置「宠物问诊」「宠物急救」「附近宠物医院」等关键词 | 低 | 长尾自然流量 |
| 种子内容 | 官方好帖 + 精选案例，保证新用户进来有内容可看 | 低 | 降低首屏流失 |

### 2.2 分享与裂变

- **帖子分享**：问诊记录脱敏后生成分享卡，带「AI 初判 + 就医建议」钩子。
- **急救工具**：离线急救指南可独立分享，急症场景传播快。
- **宠物卡**：宠物档案生成可爱卡片，满足晒宠需求。
- **邀请机制（规划）**：邀请好友完成首次问诊，双方获得深度报告次数；避免现金激励带来的低质用户。

### 2.3 留存设计

| 留存杠杆 | 机制 | 目标 |
|---|---|---|
| 健康提醒 | 疫苗/驱虫/复诊到期推送 | 提醒完成率 ≥ 60% |
| 记录沉淀 | 每次问诊自动归档，形成宠物健康时间线 | 二次问诊率 ≥ 35% |
| 广场互动 | 点赞/评论/审核通知 | 周互动率 ≥ 15% |
| 周期内容 | 每周养护贴士、季节病提醒 | 7 日留存 ≥ 25% |
| 多宠家庭 | 多宠档案与家庭共享（规划） | 多宠用户占比 ≥ 20% |

### 2.4 核心指标

| 层级 | 指标 | 定义 | 首年目标（假设） |
|---|---|---|---|
| 北极星 | 周完成问诊用户数 | 一周内至少完成 1 次问诊的去重用户 | 3,000 |
| 获取 | 建档转化率 | 新用户中完成宠物建档的比例 | ≥ 55% |
| 激活 | 首问完成率 | 建档后 24 小时内完成首次问诊 | ≥ 45% |
| 留存 | 7 日 / 30 日留存 | 次日仍回访的比例 | 25% / 12% |
| 变现 | 付费转化率 | 月活中购买会员/增值服务 | 3%–5% |
| 治理 | 审核时效 | 帖子从提交到审核完成 | 中位数 ≤ 4 小时 |

> 目标为立项假设，灰度期用真实数据校准，不对外承诺。

## 3. 运营机制

### 3.1 内容治理

| 环节 | 机制 | 责任 | 时效 |
|---|---|---|---|
| 发帖审核 | `pending` → 人工审核 → `approved/rejected` | 运营 | 4 小时内 |
| 举报处理 | 用户举报 → 后台队列 → 下架/驳回并通知 | 运营 | 24 小时内 |
| 官方内容 | 每周 2–3 篇官方好帖，覆盖季节病、疫苗、驱虫 | 内容 | 每周 |
| 知识库 | 每月补充/修订，兽医顾问复核 | 内容 + 兽医 | 每月 |
| 违规账号 | 累计违规限制发帖，严重者封禁 | 运营 | 按规则 |

### 3.2 社区氛围

- 新用户首帖引导：模板化标题（品种 + 症状 + 持续时间），减少「一句话求助」。
- 优质内容激励：精选、官方转发、勋章（规划），不直接用现金。
- 负向治理：广告、焦虑营销、伪医疗建议是重点打击对象；建立关键词与人工双审。
- 急救场景：急症帖自动置顶「立即就医」提示，避免社区建议延误。

### 3.3 数据与反馈

- 每周看板：新增、建档、问诊、记录、提醒、广场互动、审核量、AI 失败率。
- 每月复盘：留存分层、渠道 ROI、内容供给、投诉类型。
- 用户反馈：设置页意见入口（规划）、应用内问卷、种子用户群。
- 故障响应：云函数错误率、模型超时、内容安全拦截量告警。

## 4. 商业闭环

### 4.1 收入结构（规划）

| 收入源 | 内容 | 定价假设 | 启动条件 |
|---|---|---|---|
| 会员订阅 | 深度报告、多宠家庭包、历史趋势、优先响应 | ¥9.9/月，¥68/年 | 问诊留存稳定后 |
| 增值包 | 单次深度报告、宠物体检解读 | ¥3–9/次 | 报告质量验证后 |
| 医院合作 | 预约导流、体检套餐、到店核销 | 按线索/成交分成 | 有 3–5 家合作医院 |
| 品牌内容 | 宠物食品/用品官方好帖、活动 | 按项目报价 | 月活 ≥ 1 万 |

### 4.2 成本结构

| 成本项 | 说明 | 控制手段 |
|---|---|---|
| 云开发 | 云函数调用、数据库读写、存储/流量 | 缓存、分页、图片压缩、冷数据归档 |
| 模型调用 | 文本/视觉 token | 知识库 top 3–5、工具轮次上限、失败快速降级 |
| 内容审核 | 人工审核与客服 | 先审后发 + 举报优先 + 志愿者/兼职 |
| 合规 | 兽医顾问、资质、隐私审计 | 按阶段投入，优先保证医疗表述合规 |

### 4.3 商业原则

1. **急症不设付费墙**：急救指南、急症提示、附近医院始终免费。
2. **不利用焦虑收费**：付费点是「更深度、更长期」的服务，而不是「不给钱就不给建议」。
3. **不做诊断/处方**：所有付费内容仍受医疗边界约束。
4. **合作机构可追溯**：医院合作需资质审核，展示合作标识与投诉入口。
5. **先验证再扩张**：会员先小范围测试，避免在留存不足时强行变现。

## 5. 后续版本迭代

### V2.1 合规与上线（第 1–2 月）

- 替换默认管理员口令、移除 `ADMIN_OPENIDS`、真实短信。
- 订阅消息模板接入与定时推送。
- 图片 `mediaCheckAsync` + AI 输出二次审核。
- 数据库索引/权限、隐私政策、类目资质。
- 清理 `pages/featured` 孤儿页与 `package.json` 模板残留依赖。

### V2.2 AI 与问诊增强（第 3–4 月）

- 多轮上下文：请求透传 `recentMessages`，按预算裁剪。
- 8 类意图路由：咨询/症状/用药/疫苗/驱虫/行为/急诊/闲聊。
- 急症服务端硬拦截：命中急症词直接返回红色结构，不进入模型。
- 记录筛选/搜索、体重历史与趋势。
- 聊天复制、重新生成、清空会话。

### V2.3 体验与社区（第 5–6 月）

- 语音输入（录音 + ASR），降低输入门槛。
- 意见反馈入口、登录态自动续期。
- 广场话题/标签、优质作者认证。
- 分享卡片与邀请机制。
- 管理后台数据看板与审核 SLA 提醒。

### V3.0 商业化试点（第 7–12 月）

- 会员订阅与深度报告小范围付费测试。
- 医院预约/体检套餐合作试点。
- 多宠家庭共享、宠物健康时间线导出。
- 向量检索/重排，提升 RAG 召回。
- 若验证成立，再考虑多端（H5/App）与开放 API。

## 6. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 医疗合规 | 审核驳回、下架 | 明确「初判/建议」定位；不确诊、不开处方；兽医顾问复核；保留免责声明 |
| AI 幻觉 | 错误建议 | RAG 约束、低温度、结构化输出、急症规则优先、人工抽检 |
| 内容安全 | 违规 UGC | 先审后发、举报、图片/文本双校验、违规账号处置 |
| 成本失控 | 模型/云开发费用 | 预算上限、工具轮次限制、缓存、按需降级 |
| 隐私与数据 | 信任与合规 | 最小化采集、`_openid` 隔离、删除入口、日志脱敏 |
| 依赖单一模型 | 服务中断 | 多视觉模型回退、本地规则兜底、可切换供应商 |
| 运营人力 | 审核积压 | 审核 SLA、举报优先、志愿者/兼职、自动化初筛 |
