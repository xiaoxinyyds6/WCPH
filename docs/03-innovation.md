# 03 · 创新点说明

> 对应文档规范 **c**：AI 应用、场景、产品、技术、商业模式、用户体验六个维度。
> 原则：只写能落到代码或数据上的差异；未落地的一律标注「规划中」。

## 0. 一句话

不是「给聊天机器人套一个宠物皮肤」，而是把**一次问诊**做成一条可追溯、可执行、可治理的健康服务链：多模态初判 → 结构化档案 → 周期提醒 → 社区互助 → 急症兜底。

## 1. AI 应用创新：两阶段视觉诊断 + 可控 Agent

| 维度 | 常规做法 | 本项目做法 | 证据 |
|---|---|---|---|
| 图像问诊 | 图片 + 问题一次性丢给视觉模型 | **观察师**先做 OCR 与逐图病灶观察，输出关键词/报告；再用「描述 + 关键词」二次检索知识库；最后由**审查员**结合图片、报告、资料交叉验证 | `cloudfunctions/assistant/index.js` 两阶段链路 |
| 知识注入 | 靠模型记忆 | 私有知识库约 875 条，按标题 +3、正文 +1 加权检索，Top 3–5 注入提示词 | `kb_seeds_v4..v9.js`、`searchKb()` |
| 工具调用 | 纯文本问答 | `glm-4-flash` Function Calling，可查实时天气、检索知识库，最多 3 轮 | `MAX_TOOL_ROUNDS=3`、`runTool()` |
| 稳定性 | 失败即报错 | 视觉模型逐级回退；预算不足时用已有信息兜底；前端再回退本地规则 | `VISION_MODELS`、`util.aiConsult()` |

**差异点**：把「看图」和「下判断」拆成两个角色，减少单模型既当描述者又当诊断者的自相矛盾；知识库参与两次检索，让图片里的细节真正影响结论。

**边界**：不确诊、不开处方、不给剂量；图像链路未做图片内容安全。

## 2. 场景创新：从「一次问答」到「一条健康链」

| 环节 | 传统问诊工具 | 本项目 |
|---|---|---|
| 问诊前 | 直接开聊，缺少背景 | 宠物档案（品种/年龄/体重/疫苗/驱虫）自动带入提示词 |
| 问诊中 | 文字为主 | 结构化拍照表单（类型/患处/病程/瘙痒/食欲/疫苗）+ 图片/视频留证 |
| 问诊后 | 聊天记录即结束 | 一次问诊一个「档案袋」，可回看、重命名、补充问诊 |
| 跟进 | 用户自己记 | 六类健康提醒，周期完成自动排下一次 |
| 复用 | 无法沉淀 | 脱敏发布到广场，形成经验互助与内容治理 |

**差异点**：问诊结果不是终点，而是记录、提醒、社区内容的起点。宠物档案与提醒把「一次性咨询」拉长成「长期健康管理」。

## 3. 产品创新：先审后发的宠物健康社区

| 设计 | 作用 | 证据 |
|---|---|---|
| 发帖 `pending` → 管理员 `approved` | 把违规内容挡在大厅之外 | `square.publish`、`adminAudit` |
| 举报 → 下架 `rejected` + 原因 | 保留证据链，不物理删除 | `square_reports`、`adminHandleReport` |
| 脱敏发布 | 只带品种/部位/摘要，降低隐私暴露 | 记录详情/对话页发布入口 |
| 精选 / 官方双栏 | 冷启动阶段保证内容质量 | `featured`、`officialList` 自动补种 |
| 审核/互动通知 | 作者知道结果，减少重复申诉 | `square_notifications` |

**差异点**：宠物社区常见问题是广告、焦虑营销与伪医疗建议；本项目用「审核 + 举报 + 官方内容」把治理成本前置，而不是事后删帖。

## 4. 技术创新：在 60 秒云函数预算内做多模型编排

| 难点 | 解决方式 | 证据 |
|---|---|---|
| 云函数 60s 上限 | 总预算约 52s；单轮 `min(25s, 剩余)`；剩余 <12s 不再发起新轮 | `assistant/index.js` 超时与预算判断 |
| 多图模型差异 | 4.6V 支持多图，4V 只取第一张；失败自动切换 | `VISION_MODELS` 顺序回退 |
| 模型输出不稳定 | 强制 JSON + 剥离代码块 + 首尾花括号截取 | `parseJson()` |
| 关键词检索召回有限 | 中文 2 字滑窗 bigram + 标题加权，零向量库成本 | `tokenize()`、`searchKb()` |
| 多端协议不一致 | 云函数统一 `{ ok, data, msg }`，前端统一 toast | `utils/cloud.js` |
| AI 链路难测 | `Module._load` 拦截 `wx-server-sdk`/`https`，内存模拟数据库与模型 | `test/assistant-image-flow.test.js`（7 个用例） |

**差异点**：不是「调通 API」就结束，而是把超时、重试、降级、解析、测试都做成可验证的工程约束。

## 5. 商业模式创新：基础免费 + 健康服务增值（规划中）

> 当前全部功能免费，以下为落地设计，尚未上线收费。

| 层级 | 内容 | 付费点 | 现状 |
|---|---|---|---|
| 基础层 | 建档、文字问诊、记录、提醒、急救、附近医院 | 免费 | ✅ 已实现 |
| 增值层 | 深度报告、多宠家庭包、历史趋势、优先响应 | 会员订阅 | ⏳ 规划 |
| 服务层 | 医院预约/体检套餐导流、品牌养护内容 | 服务佣金/合作 | ⏳ 规划 |
| 内容层 | 官方好帖、专家专栏 | 品牌合作 | ⏳ 规划 |

**为什么成立**：问诊是高频入口，档案与提醒带来留存，广场带来自然流量；变现放在「深度服务」而非「紧急医疗决策」上，避免利用焦虑收费。

**合规边界**：不导诊到无资质机构；不按问诊次数对急症用户设付费墙；医疗建议始终免费可见。

## 6. 用户体验创新：让不确定的人知道下一步

| 设计 | 用户收益 | 证据 |
|---|---|---|
| 红/黄/绿三级 | 一眼判断紧急程度，而不是读完整段建议 | `level` 字段与前端配色 |
| 急症词硬提示 | 呼吸困难、大出血、中毒、抽搐等直接建议立即就医 | 本地规则 + 提示词 |
| 免责声明前置 | 首次问诊弹窗确认，降低误解 | `disclaimer_agreed_v1` |
| 失败不白屏 | 医院接口失败展示演示数据与原因；AI 失败回退规则 | `demoMode`、`errMsg` |
| 少输入 | 快捷问题、档案自动带入、拍照表单选项化 | `chat`、`consultForm` |
| 可回溯 | 档案袋、记录分类、浏览历史 | `records`、`history` |

**差异点**：把「医疗不确定性」做成界面语言（颜色、分级、就医时机、禁止事项），而不是一段需要用户自己解读的长文本。

|---|---|---|
