> 对应文档规范 **f**：若为往届作品迭代，明确标注优化部分；无过往成果填「无」。

## 1. 结论

**无。** 本项目不是往届参赛作品的迭代版本，没有往届提交、获奖或公开展示记录。

## 3. 优化明细

| 维度 | 迭代前 | 当前版本 | 证据 |
|---|---|---|---|
| AI 问诊 | 关键词规则回复，急症词短路 | 智谱 `glm-4-flash` 文本 Agent，支持工具调用与结构化输出 | `cloudfunctions/assistant/index.js` |
| 图像问诊 | 单次视觉调用或本地模拟 | 观察师（OCR/影像观察）→ 联合检索 → 审查员终判 | 两阶段链路、7 个单测 |
| 知识库 | 无 | 约 875 条私有知识，标题/正文加权检索，管理员可增删 | `kb_seeds_v4..v9.js`、`kb_docs` |
| 问诊记录 | 聊天记录即结束 | 一次问诊一个档案袋，支持重命名、回看、转提醒、发布 | `records`、`recordDetail` |
| 健康提醒 | 仅应用内待办 | 六类提醒 + 周期自动排下一次 + 订阅消息链路（模板待配） | `reminder`、`notify` |
| 问诊广场 | 无 | 大厅/精选/官方、搜索、点赞、收藏、评论、举报、通知 | `square`、`square_posts` |
| 内容治理 | 无审核 | 发帖 `pending`、管理员审核、举报下架、下架原因 | `adminAudit`、`adminHandleReport` |
| 管理后台 | openid 白名单 | 管理员账号体系 + 账号管理/审核/举报/知识库/概览 | `admins`、`pages/admin` |
| 登录方式 | 手机号授权/验证码 | openid 一键登录为主，验证码/账号密码为备选 | `login.wxLogin` |
| 视觉风格 | 蓝色主题、内联列表 | 青绿主题；「我的」改为入口菜单 + 独立列表页 | `app.wxss`、`mine` |
| 工程质量 | 无自动化测试 | 7 个离线单测；统一 `{ ok, data, msg }` 协议；文档链接校验 | `test/`、`utils/cloud.js` |
| 文档 | README + 4 篇技术文档 | README 门面 + a–g 七篇 + AI/数据模型/部署三篇深入 | `docs/` |

## 4. 计划与实际的偏差

| 项 | v1.0 规划 | 实际 | 处理 |
|---|---|---|---|
| Tab 结构 | AI 助手 / 记录 / 我的 | AI 问诊 / 问诊广场 / 我的 | 记录入口收进「我的」；文档按实际写 |
| 广场 | 明确不做 UGC | 已上线问诊广场 | 补齐审核、举报、通知 |
| 登录 | 微信手机号授权 | openid 一键登录 | 降低门槛；验证码保留为演示 |
| 多轮上下文 | 透传历史消息 | 仅当前问题 + 档案 | 列入 Backlog |
| 急症拦截 | 服务端硬拦截 | 提示词 + 本地规则 | 列入 Backlog |
| 订阅消息 | 全链路推送 | 授权/定时/发送已就绪，模板为空 | 上线前配置模板 |

## 5. 后续如何记录迭代

- 每次发版在本文追加一行：日期、版本、代表提交、变化、影响范围。
- 若未来参加往届作品的再次迭代，在本节明确写「基于第 X 届作品《名称》」，并单列「本届优化点」，不要把仓库自身迭代写成往届成果。
- 版本号与 `spec.md` 的文档版本保持一致；`package.json` 的 `1.0.0` 仅为工程版本，不代表产品版本。
